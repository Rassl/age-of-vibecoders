# Corridor Assault — Frozen Implementation Spec

_Produced by an 11-agent design workflow: 4 design lenses, 3 competing architectures, 3 judges, 1 synthesis._

## Summary

FROZEN SPEC — "Age of Vibecoders". Architecture: Three-Layer Treadmill (headless sim / one-way event bus / ordered view pipelines), the panel's 2-of-3 winner, with every graft the judges named.

THE FIVE RULES EVERYTHING ELSE FOLLOWS FROM:
1. `src/sim/**` never imports three.js. Enforced mechanically: `tools/harness.mjs` imports every sim module in bare node as an npm `prebuild` step and throws on a three import. This buys headless balance runs, deterministic replay, and a hard answer to "sim bug or render bug".
2. Tick order is data. `src/sim/systems.js` exports a flat `[{name, fn}]` array; the debug overlay toggles entries by name to bisect a gameplay bug in thirty seconds.
3. The bus is one-directional. Sim emits facts, presentation listens; sim→sim causality is direct function calls. A DEV assertion rejects any subscriber registered from `sim/`. One `src/reactions.js` owns every consequence of every topic, so "what happens when a barrel dies" is one function.
4. Entities are plain objects in typed pools with two-phase death and generation-tagged handles. Objects, not struct-of-arrays: at n≤220 the whole sim is ~1.5ms and a debugger showing `{x:2.1, hp:40, kind:'walker'}` is worth more than the microseconds.
5. One file owns every number (`src/config.js`, DERIVED constants computed at boot), one file owns `soldierCount` (`src/sim/roster.js`).

CONFLICTS RESOLVED, ONE LINE EACH:
- Corridor 9.0u (not 6.4 / 12) — three readable 3u lanes; camera moved to (0, 6.5, 12.4) so a 62° vFOV portrait frames exactly 9.5u at the squad plane, which 6.4u-era camera numbers did not.
- Squad cap 40 (not 60) — the cap is the entire variance-control story; 60 stops reading as countable individuals.
- Per-soldier DPS 10 × tier [1.0, 1.6, 2.4, 3.6] (not 12.5 or 24) — only model where in-run tier steps are exactly 1.5×, which is what makes the weapon-vs-soldier crossover N*=2k tier-independent.
- Fixed 1/60, max 3 substeps (not 1/120) — every spring uses the exponential-exact `1-exp(-k·dt)` form, so 120Hz buys nothing.
- Hitscan ray resolved at fire time, damage applied from a deferred queue keyed to tracer arrival, `combat.impactDelay` the knob (ship at 0, tune to 0.08) — Judge 1's top graft; converts the one genuinely unresolved feel question into a slider instead of a refactor.
- Phyllotaxis formation (not hex rings) — slot i is a pure function of index, so gaining soldier N never moves 0..N−1.
- Barrel breach = `clamp(ceil(N·F·(hpRem/hpMax)^1.5), 1, ceil(N·0.6))` (not a flat divisor) — scale-free from N=3 to N=40, and the 1.5 exponent makes a near-kill nearly free, which is what teaches commitment.
- ONE fail condition: soldiers reach 0. No 1-soldier floor, no revive — the 0.55s i-frame caps bleed at 1.82/s and the 60% breach cap means no single event wipes a squad of ≥2, so reaching 0 always takes sustained failure and is always narratable.
- Relative drag, 55% of screen width crosses the corridor (not 1:1) — 1:1 at 9.5u visible width needs 95% of screen width, unreachable one-handed.
- Run 110s corridor + 10-27s boss (not 78s, not 140s+) — long enough for a 3→40 arc, short enough that a failed run costs under three minutes.

BALANCE IS VALIDATED, NOT ASSERTED. I ran the full economy in node across six skill levels, modelling the term the design lenses all omitted: aim efficiency (a player who cannot hold a lane delivers a fraction of nominal DPS — the direct mechanical consequence of "bullets go straight, you aim with your body"). Result is monotone with a clean pass line at aim ≈ 0.75:
  EXPERT (aim 0.95) → 40 soldiers, minigun, boss 14,339hp, TTK 10.5s → WIN
  GOOD (0.84) → 36 soldiers, minigun, TTK 12.3s → WIN
  COMPETENT (0.78) → 15 soldiers, shotgun, TTK 27.0s vs 42s survival → WIN, nail-biter, hits the rage timer
  SHAKY (0.69) / CLUMSY (0.61) → wipe at t=74
  BAD (0.40) → wipe at t=30
Barrel HP is priced against NOMINAL squad DPS but killed at EFFECTIVE DPS, which is what makes aim the load-bearing skill rather than a garnish. The screenshot's 62 and 210 fall out of the curve at beats 2 and 3 (`hpScale` 0.40 and 1.00) — a calibration check, not a coincidence.

WHAT I REFUSED: auto-aim (deletes the mode), BatchedMesh, three-mesh-bvh, Raycaster for gameplay, any physics library, EffectComposer/UnrealBloom, shadow maps, PointLights, MeshPhysicalMaterial transmission, runtime fillText, AnimationMixer, GLTFLoader, logarithmicDepthBuffer, WebGPURenderer, and any bullet broadphase (hitscan deletes the category).

48 files, ~7.5k lines. Blast radius for a common edit is 1-2 files: a new enemy is one row in `data/enemies.js`; a new pickup is one branch in `sim/props.js`; a new weapon is one row in `data/weapons.js`.

### `src/config.js` _(self-contained)_

### `src/util/pool.js` _(self-contained)_
EXISTS — extend with two additions that each delete a bug class. (1) Per-slot generation counter plus makeHandle(pool,i) and deref(pool,handle) returning null on mismatch, so a deferred impact scheduled at t cannot damage whatever recycled into that slot by t+0.1s. (2) Two-phase death: markDead(item) sets a flag and never releases; only sim/reap.js releases. Together these make three systems killing the same zombie in one substep idempotent and make mid-iteration release impossible.
- **exports:** Pool, makeHandle, deref, markDead, isDead
- **depends:** none

### `src/core/loop.js` _(self-contained)_
Time authority and the ONLY requestAnimationFrame in the codebase. Raw dt clamp at 0.05s (a backgrounded tab returns a multi-second delta and every entity would teleport through every collision test on the first frame back), the hitstop/timescale stack, fixed-step accumulator with a hard 3-substep ceiling (excess time is DROPPED, not simulated, so a hitch cannot death-spiral), interpolation alpha, pause and step-once for debugging, and a rolling frame-time window for the DPR governor. The sole place dt is ever scaled.
- **exports:** createLoop, pushHitstop, setTimescale, getAlpha, frameStats
- **depends:** src/util/math.js

### `src/core/bus.js` _(self-contained)_
The event contract AND the queue. Exports the frozen EV topic enum (adding a topic is a deliberate, visible act) and a zero-allocation ring of 2048 pre-allocated payload records with fixed fields {type,x,y,z,a,b,id}. Layer-tagged subscribe; drain() called exactly ONCE per frame after all substeps, never per substep. Overflow drops the OLDEST and bumps a DEV counter — safe by construction because the ring carries only cosmetic and audio consequences. A DEV assertion rejects any subscriber registered from a sim/ module, mechanically enforcing the one-way rule.
- **exports:** EV, createBus, ringOverflowCount
- **depends:** none

### `src/core/input.js` _(self-contained)_
Pointer and key input, and nothing else — touches the DOM but never three.js and never sim state, so the firewall holds. Pointer Events only (one code path for mouse and touch) with setPointerCapture; sums x-deltas from every pointermove INCLUDING getCoalescedEvents() so a 120Hz flick is never under-read on a 60Hz sim; primary-pointer tracking with promotion of a secondary finger and re-anchoring so the squad never jumps; hold-on-release with no inertia and no recentering; pointercancel/blur/pointerleave end the session. drainDx() returns and ZEROES the accumulated CSS-pixel delta and is called exactly once per frame. Also A/D keys, the record/playback tape hook, and preventDefault on touchstart/touchmove.
- **exports:** createInput, drainDx, isPointerDown, keyAxis, setTape, recordTape
- **depends:** src/config.js

### `src/sim/world.js`
The entire mutable run state in one inspectable object: every Pool (soldiers, joiners, zombies, props, impacts, shockwaves, boss), the scalars (runTime, distance, scrollSpeed, anchorX, targetX, targetXRaw, velX, soldierCount, peakSoldiers, tier, phase, iframeTimer, bossHp, bossPlate, seed, rng), and the bus reference. resetWorld(seed) sets every pool size to 0 and rewinds every scalar — that IS the entire sub-100ms restart. Allocates only at boot, never during play.
- **exports:** createWorld, resetWorld, PHASE, nominalDPS, squadRadius

### `src/sim/steer.js`
The single most feel-critical file. Consumes this substep's share of the frame's accumulated dx: targetXRaw += dx * CFG.input.dragGain, one 45ms exponential low-pass to kill touch-digitizer jitter (jitter ONLY, never feel), clamp to ±4.2, clamp implied lateral speed to 26 u/s, then spring anchorX toward it at 60ms tau. Produces the GAMEPLAY-TRUTH centroid and velX that every muzzle origin, contact test and barrel overlap reads. Hold-on-release: no inertia, no recentering.
- **exports:** steerStep
- **depends:** src/sim/world.js, src/config.js, src/util/math.js

### `src/sim/squad.js`
Who is in the squad and where they are, in GAMEPLAY truth only (visual springs live in view/characters.js — the split is architectural, not conventional, so the two can never be conflated). Precomputed phyllotaxis slot table (Float32Array 40x2, theta = i*2.39996, r = spacing(n)*sqrt(i), ellipse-squashed 0.75x/1.35z, radius clamped 2.1u), distance-sorted stable slot reassignment on any count change so losing a mid-crowd soldier never snaps the formation, a 2-iteration uniform-grid separation push, per-soldier fire timer and recoil impulse scalar, and the joiner actors that sprint in from a broken bubble at 16 u/s and merge staggered 60ms apart. frontRank(n) returns the 14 lowest-z slot indices for the visible-tracer cap.
- **exports:** buildSlotTable, reassignSlots, squadStep, updateJoiners, spawnJoiners, frontRank, formationRadius, slotOffset
- **depends:** src/sim/world.js, src/config.js, src/util/math.js, src/core/bus.js

### `src/sim/scroll.js`
The treadmill, in one pass: advance runTime and distance, evaluate scrollSpeed(t) ONCE for the whole substep, then add scrollSpeed*dt to every prop, zombie, joiner, shockwave and decal z, and mark anything past z=+12 dead. The squad never translates forward — it lives at z≈0 forever, which kills float drift and makes the boss's 'stops the world' moment a one-line speed clamp.
- **exports:** scrollStep
- **depends:** src/sim/world.js, src/curves.js, src/core/bus.js

### `src/sim/targets.js`
The storage-agnostic blocker record — the only data structure in the game. Each substep it packs every live zombie, barrel, bubble and the boss into a shared flat array of {kind, handle, x, halfWidth, z, hp, blocksBullets}, sorted near-to-far by z with an insertion pass over a nearly-sorted 24-entry array (O(n) in practice). The ray loop then never branches on entity kind or storage layout, so adding a shield zombie or an armoured crate is a spawn-site change with zero edits to hitscan.
- **exports:** rebuildTargets, targets, targetCount, TKIND, firstBlocker
- **depends:** src/sim/world.js, src/util/pool.js

### `src/sim/combat.js`
Shots and their consequences, with the damage choke point. Per-soldier fire timers at the tier rate with a golden-ratio phase stagger; every timer produces REAL damage (strictly linear DPS) but only the front 14 emit a tracer event, with per-tracer damage folded to nominalDPS/visibleShooters. Casts a straight +Z ray from each muzzle x through the target list — blocking order zombies(tier<=2) / barrels / bubbles, tier-3 pierce through 2 zombies — and pushes {handle, damage, dueTime, hitPoint} onto a deferred impact queue. queueDamage() accumulates into a Float32Array ledger; flushDamage() applies it ONCE per target, detects each death exactly once, routes overkill into pierce, and emits. Also owns the 8Hz displayed-HP lerp the number view reads. CFG.combat.impactDelay at 0 is exact hitscan; at 0.08 the number ticks when the tracer lands.
- **exports:** fireStep, impactsStep, flushDamage, queueDamage, displayHP, impactsDiscarded
- **depends:** src/sim/world.js, src/sim/targets.js, src/sim/squad.js, src/data/weapons.js, src/config.js, src/util/pool.js, src/core/bus.js

### `src/sim/zombies.js`
Zombie pool lifecycle only: spawn from an archetype row with HP from zombieHP(t), forward advance, and rate-limited lateral homing toward anchorX at 2.5 u/s so they can be outrun sideways but not trivially. Behavior differences are one ~20-line switch on archetype.behavior ('WALKER' | 'RUNNER' | 'BRUTE' | 'SWEEP'). Adding an enemy that reuses an existing behavior does not touch this file at all. Contact resolution deliberately lives in collision.js, not here.
- **exports:** spawnZombie, spawnCluster, spawnSweep, zombiesStep, liveZombies
- **depends:** src/sim/world.js, src/data/enemies.js, src/curves.js, src/util/math.js, src/core/bus.js

### `src/sim/props.js`
Barrels and bubbles: one pool, one shape, one scroll path, one HP field, one z-crossing hook — only the resolution branches differ, so the shared 80% is written once. Barrel crossing runs the centroid + FIXED 0.6u radius overlap test (never the crowd's real width, or growing the squad would be a punishment) and queues the proportional breach loss; a clean dodge emits a DODGED flourish. Bubble crossing is a free miss with a MISSED toast and zero penalty. Bubble death spawns joiners or bumps the weapon tier (converting to +6 soldiers at max tier). Barrels never halt the scroll — a lane runner that stops reads as a physics bug.
- **exports:** spawnProp, propsStep, resolveCrossings, activeProps, PROP_KIND, PROP_ROLE
- **depends:** src/sim/world.js, src/sim/squad.js, src/sim/roster.js, src/curves.js, src/util/pool.js, src/core/bus.js

### `src/sim/collision.js`
All body-vs-body overlap in the game, at one specific pipeline position. A single scalar |z - squadZ| < 2.5 band reject discards ~95% of zombies before any real test (the squad occupies a ~2u z band), then per-soldier squared-distance contact with the 0.55s squad i-frame window, plus boss shockwave-vs-squad. Everything is 2D (x,z) on squared distances; y is NEVER read, which removes the whole bug class where a soldier's idle bob causes a phantom miss. Queues soldier kills through roster; never mutates the count.
- **exports:** collisionStep
- **depends:** src/sim/world.js, src/sim/squad.js, src/sim/roster.js, src/config.js, src/core/bus.js

### `src/sim/boss.js`
The only entity with a real state machine, isolated so the finale can be tuned or skipped without touching the corridor. Entry (scroll decelerates 18→2→0 over 1.6s, camera handoff event), HP from bossHP(nominalDPS) with three armour plates at 100/66/33% each granting a 1.2s stagger, slam cadence spawning two expanding shockwave lines with a 2.2u gap to slide between, runner add spawns via sim/zombies, the 30s rage timer that halves both cadences, and the death sequence. Runs BEFORE collision so a slam's shockwave resolves in the step it is spawned rather than 16ms late.
- **exports:** spawnBoss, bossStep, bossActive, bossHpFrac, bossPlateIndex
- **depends:** src/sim/world.js, src/sim/zombies.js, src/sim/roster.js, src/curves.js, src/core/bus.js

### `src/sim/roster.js`
THE ONLY MUTATOR OF soldierCount, and the repair for the winning architecture's one real correctness hole. queueAdd()/queueRemove() accumulate requests and update a synchronous pendingCount() that props.js reads so a breach penalty can never try to remove more soldiers than will exist. commitRoster() then applies the whole substep's deltas ONCE: enforces the 0.55s i-frame, clamps to the 40 cap, fires exactly ONE formation re-slot, emits exactly ONE SOLDIER_COUNT_CHANGED carrying the net delta and dominant cause, and raises FAIL at zero. Without this, a breach costing four soldiers fires four counter punches, four vignette pulses, four haptics and four re-slots.
- **exports:** queueAdd, queueRemove, pendingCount, commitRoster, peakSoldiers
- **depends:** src/sim/world.js, src/sim/squad.js, src/config.js, src/core/bus.js

### `src/sim/reap.js`
The single pass that walks every pool BACKWARDS, releases everything marked dead, bumps the slot generation, and emits despawn events. Its own file precisely because it must happen in exactly one place at exactly one pipeline position — a second reap call anywhere else is a bug, and a file makes that greppable.
- **exports:** reapAll
- **depends:** src/sim/world.js, src/util/pool.js, src/core/bus.js

### `src/sim/director.js`
What exists and when. The beat cursor over data/encounters.js keyed on distance travelled, the wave scheduler converting threatBeta(t) into a spawn rate (capped 12/s with brutes absorbing overflow HP), the scroll ramp, and the run phase machine (INTRO / CORRIDOR / CRESCENDO / LULL / BOSS / WIN / FAIL). Runs LAST in the pipeline so a newly spawned entity is never moved, shot or collided in the step it was created — that is what makes the 72u spawn horizon exact rather than approximate, and the horizon is the budget the entire economy is written against. jumpToBeat(i) teleports the run for tuning.
- **exports:** directorStep, jumpToBeat, currentBeat, restartRun, runResult
- **depends:** src/sim/world.js, src/data/encounters.js, src/curves.js, src/sim/props.js, src/sim/zombies.js, src/sim/boss.js, src/core/bus.js

### `src/view/renderer.js` _(self-contained)_
WebGLRenderer setup with ACESFilmicToneMapping and exposure 1.05 enabled on DAY ONE (turning it on later means re-picking every color), outputColorSpace SRGB, shadowMap explicitly off, near 1 / far 200 for a 200:1 depth ratio that kills most road z-fighting for free. Fixed 9:16 portrait letterbox with debounced resize, the adaptive DPR governor (steps down 2.0→1.5→1.25→1.0 after 30 consecutive frames over 20ms, and NEVER back up — hysteresis, because an oscillating resolution is far more noticeable than a slightly soft one), antialias only when DPR<=1.5, and worldPerPx recomputed once per resize for the input gain.
- **exports:** createRenderer, resizeRenderer, governDPR, worldPerPx, viewport
- **depends:** src/config.js

### `src/view/scene.js` _(self-contained)_
The static world: scene root, HemisphereLight(#BFD8FF/#C89B62, 0.55) + DirectionalLight(#FFE7C2, 1.15) from upper-left-front at 40° elevation + AmbientLight(#4A5B7A, 0.20), NO shadow maps and NO PointLights ever, FogExp2(#D9BC8E, 0.0135), and a gradient sky dome whose bottom stop is EXACTLY the fog color or a horizon seam appears. With box-based art the light DIRECTION is the modelling: a 40° side key gives every box face a distinct value where a top-down light would flatten everything into unreadable blobs. Exposes setDanger() for the pre-boss red lighting shift.
- **exports:** createScene, updateSceneTime, setDanger

### `src/view/camera.js`
The entire camera rig in one file, because every one of these is a write to the same transform and splitting them guarantees they fight. Base pose (0, 6.5, 12.4), lookAt (anchorX*0.25 + velX*0.06, 1.0, -7.5), vFOV 62 — geometry chosen so a 9:16 portrait frames exactly 9.5u at the squad plane, so the 9u corridor's rails sit at the frame edges. PARTIAL lateral follow at 0.50 (1.0 pins the squad to screen centre and the drag reads as dead), log2 growth dolly at CONSTANT pitch (y = 1.0 + 0.2773*(z+7.5)), velocity counter-roll, speed-linked FOV plus impact punch, trauma-based DETERMINISTIC value-noise shake (never per-frame Math.random, which reads as a rendering glitch), and the boss punch-in and kill-cam orbit. Split time base: trauma/shake/FOV punch on SCALED dt so a 70ms hitstop freezes the shake and reads as impact; follow spring and dolly on RENDER dt so they never substep-jitter.
- **exports:** createCameraRig, updateCamera, addTrauma, punchFov, setCameraMode
- **depends:** src/sim/world.js, src/config.js, src/util/math.js, src/view/scratch.js, src/core/bus.js

### `src/view/materials.js` _(self-contained)_
Every shared material and every onBeforeCompile injection, centralised so a three version bump is one file to fix: rim light (col += rimColor * pow(1-dot(N,V), 3.2) * 0.55 — the cheapest depth separator that exists and what keeps enemies legible inside the fog), per-instance aFlash white mix, vertex-shader limb swing driven by aPhase, barrel vertical HP fill wipe with a hot emissive boundary band, additive fresnel bubble shell, sky gradient. EVERY patched material sets a stable customProgramCacheKey to prevent recompile churn. ## Tick Order

1. FRAME 0 — loop.js: rawDt = min(now - last, 0.05). Clamp FIRST: a backgrounded tab returns a multi-second delta and every entity would teleport through every collision test on the first frame back. scaledDt = rawDt * timescale (the hitstop stack). accumulator += scaledDt. This is the ONLY place in the codebase dt is ever scaled — hitstop must scale the simulation, not the render, or the springs and the sim disagree about how long a second is.
2. FRAME 1 — input.drainDx(): read and ZERO the accumulated pointer delta exactly once, at the very top of the frame, before any substep. Reading pointer state inside the render step instead is a guaranteed full frame of invisible latency that no amount of spring tuning recovers. Compute nSubsteps for this frame, then hand each substep dx/nSubsteps — divided EVENLY, not dumped into substep 0, because the 26 u/s per-substep lateral clamp would truncate a fast flick on exactly the hitching frames where control matters most. With nSubsteps=1 (the normal case) the two are identical, so this costs nothing and only fires when it matters.
3. FRAME 2 — SUBSTEP LOOP: while (accumulator >= 1/60 && steps < 3) runStep(w, 1/60, dxShare). Capped at 3; excess accumulator time is DROPPED, not simulated, so a hitch cannot cause a death spiral. Fixed, because with a variable timestep the drag gain, DPS and closing speeds all silently change with framerate and every barrel HP number you tune is only correct on the machine you tuned it on.
4. SIM 1 — time: advance runTime and distance, evaluate scrollSpeed(t) ONCE. Absolutely first, because every system downstream must read the SAME scrollSpeed and phase for this step; if scroll ramps midway, entity A moves at 14 u/s and entity B at 14.02 and the spawn spacing quietly drifts across a two-minute run.
5. SIM 2 — steer: integrate this substep's dx share into targetXRaw, apply the 45ms low-pass (digitizer jitter only, never feel), clamp position to ±4.2 and implied lateral speed to 26 u/s, then spring anchorX at 60ms tau. Before everything else, because the mode's whole promise is that damage starts landing in the lane you just dragged into ON THIS FRAME. Any system computing a muzzle origin, a contact test or a barrel overlap before the squad has moved is computing it from last frame's position — that is the mud failure, and it is an ordering bug, not a tuning one.
6. SIM 3 — squad.formation (gameplay half): resolve per-soldier GAMEPLAY slot positions around the new anchor, advance fire timers and recoil impulses. Contact tests and muzzle origins are per-soldier, so soldier positions must be final before any test. Note the deliberate split: gameplay positions are effectively instant here, visual positions lag 90-200ms and are computed in view/characters.js at render rate, in a different layer precisely so the two can never be accidentally conflated.
7. SIM 4 — scroll: add scrollSpeed*dt to every prop, zombie, joiner, shockwave and decal z in one pass; mark anything past z=+12 dead. Before collision, not after: an object must be at its final position for this step before anything tests against it. Move-after-test gives a barrel one free frame of overlap, which is exactly the one-frame unfairness players read as the game cheating.
8. SIM 5 — zombies.move: forward advance plus rate-limited lateral homing toward anchorX (step 2's value, so they home at the squad's TRUE current position). Grouped here with joiner run-in and boss shockwave advance — these are the only entities with their own velocity on top of the treadmill. Once this completes the world is fully settled for the step and can be indexed once. Getting this wrong (indexing before self-motion) is the bug that makes rays miss a runner homing hard toward your lane, because you shot at the position it just left.
9. SIM 6 — boss.update: phase machine, plates and staggers, slam cadence spawning shockwaves, add spawns, rage timer. HERE rather than later because its shockwaves must exist before collision runs at step 10, otherwise a slam resolves a full step late and the dodge window is unfair by 16ms.
10. SIM 7 — targets.rebuild: pack every live zombie, barrel, bubble and the boss into the shared flat blocker array with x-extents, sorted near-to-far by an insertion pass over a nearly-sorted array. Exactly here: positions are final and nothing has died yet, so one index serves both the fire pass and the contact pass. Rebuilding it before movement is the classic source of 'the ray missed a zombie that was clearly there'.
11. SIM 8 — combat.fire: tick every soldier's fire timer; for each round cast a straight +Z ray from that soldier's own muzzle x and QUEUE a deferred impact {handle, damage, dueTime = now + CFG.combat.impactDelay, hitPoint}. Front-14 shooters also emit TRACER and MUZZLE events. AFTER all movement so the ray originates at the squad's post-move x against enemies' post-move z — firing before movement makes every ray miss by up to 0.53u of relative motion, comparable to a zombie's radius, and is the classic reason measured DPS never matches the spreadsheet.
12. SIM 9 — combat.impacts: pop every impact whose dueTime has arrived, deref its generation-tagged handle (discarding any whose target has been recycled, counted in DEV), and queueDamage into the ledger. Immediately after fire in the SAME substep, so that impactDelay = 0 is EXACTLY hitscan and the delay becomes a pure tuning knob rather than a structural commitment.
13. SIM 10 — combat.flushDamage: apply the Float32Array ledger ONCE per target, detect each death exactly once, route overkill into the pierce path, mark dead, emit HIT / KILL / BARREL_DEAD / BUBBLE_BREAK. Its own step and its own file because this is the most bug-prone point in the simulation: at 40 shooters converging on one 20hp walker, per-impact application silently burns most of a step's DPS into a corpse and emits the death event forty times.
14. SIM 11 — collision: |z - squadZ| < 2.5 scalar band reject, then per-soldier squared-distance contact with the 0.55s i-frame, plus boss shockwave sweep. Queues soldier removals; never mutates the count. AFTER combat, deliberately: a zombie the squad killed this step must not also eat a soldier. That ordering IS the fairness contract — 'if I shot it in time, it does not touch me' is the generous read and the one players expect; reversing it makes every near-miss feel like the game cheating.
15. SIM 12 — props.resolveCrossings: any barrel or bubble whose z crosses the squad plane this step resolves. Centroid + FIXED 0.6u radius against the barrel's x-extent (never the crowd's real width, or growing the squad becomes a punishment); proportional breach loss queued against roster.pendingCount() so it can never over-remove; free miss on a bubble. After combat so the penalty reads HP that already includes this step's damage — otherwise the last 16ms of the player's fire is silently thrown away at exactly the moment it mattered most.
16. SIM 13 — roster.commit: apply every queued add and remove ONCE. Enforce the i-frame window and the 40 cap, change soldierCount a single time, distance-sort survivors and reassign phyllotaxis slots ONCE, emit exactly ONE SOLDIER_COUNT_CHANGED carrying the net delta and dominant cause, and raise FAIL at zero. The single choke point: without it, a breach costing four soldiers fires four counter punches, four vignette pulses, four haptics and four formation reshuffles in one step.
17. SIM 14 — reap: walk every pool BACKWARDS, release everything marked dead, bump slot generations, emit despawn events. After all resolution, so three systems marking the same zombie in one substep is idempotent and nothing is swap-removed out from under an in-progress iteration.
18. SIM 15 — director: advance the beat cursor by distance, spawn the next beat and the next wave at the 72u horizon, advance the run phase. LAST, deliberately. The new content's HP blends against the player's ACTUAL nominal DPS and the window's demand ratio is measured against the squad they actually have — both only finalised by roster.commit. Spawning first would price this window's barrels against last step's squad, which is precisely the asymmetry the economy depends on. It also guarantees a freshly spawned entity is never moved, shot or collided in the step it was created, so the 72u horizon is exact rather than approximate — and that horizon is the budget the whole economy is written against.
19. AFTER ALL SUBSTEPS — bus.drain(): once per FRAME, not once per substep. A 3-substep frame would otherwise fire three explosion bursts positioned at three stale interpolation states, three audio voices for what the player perceives as one event, and would make the voice limiter's rate accounting a lie. Draining once means presentation always sees a single coherent post-step world. Dispatch every event to the one handler in src/reactions.js, which fans it out to particles, tracers, groundfx, camera trauma, hitstop, audio and HUD.
20. RENDER 1 — alpha = accumulator / (1/60). Nothing writes sim state after this point; the rest of the frame is strictly read-only over world state, enforced by a DEV assertion that fails if a view module writes a sim field.
21. RENDER 2 — camera.update(rawDt, scaledDt, alpha): partial lateral follow spring and growth dolly on RENDER dt so they never substep-jitter; trauma decay, deterministic value-noise shake and FOV punch on SCALED dt so a 70ms hitstop freezes the shake and reads as impact rather than as a stutter. BEFORE any view sync, because glyph quads and muzzle billboards orient to camera.quaternion and using last frame's camera produces a one-frame billboard lag plainly visible on barrel numbers during a roll.
22. RENDER 3 — views.sync(w, alpha): characters (visual springs, lean, recoil, gait, then a full rebuild of every instance matrix with the inlined compose, count = pool.size), ground rings, props (HP fill uniform, crack blend, bubble spin), corridor recycling. Runs at render dt with exponential damping so the crowd slosh is as smooth as the display allows on a 144Hz panel while gameplay stays locked to 60Hz.
23. RENDER 4 — fx.update(rawDt): particles, tracers, glyphs, decals, shockwaves. LAST among visual layers for two reasons: they consume positions written this frame (muzzle anchors, impact points) so they must follow the writers, and putting them at the end makes it physically impossible for a VFX system to feed back into gameplay — the dependency direction is enforced by position in the pipeline rather than by discipline. Everything that billboards reads the now-final camera.
24. RENDER 5 — hud.update(): one batched write of transform and opacity only, no reads, no layout-triggering properties, with a cached last value per element. Then audio.flush(), which runs after everything so the voice limiter sees the whole frame's events at once and can steal by priority rather than by arrival order.
25. RENDER 6 — renderer.render(scene, camera), then renderer.governDPR(frameMs). The single exit point, which makes 'is this CPU or GPU' answerable with one timer and lets the adaptive-resolution decision be made with the frame's real cost already known.
26. RENDER 7 — debug.update() (DEV only, tree-shaken from production): frame graph sample, per-system timings, counters, replay tape advance.

## Tuning Table (106 entries)

| key | value | rationale |
|---|---|---|
| `world.corridorWidth` | `9.0` | Three readable 3u lanes so a barrel and a bubble can genuinely compete. Lens 3's 6.4u cannot hold three lanes plus a 40-soldier squad; lens 4's 12u overflows a portrait frustum. Camera geometry below is derived to frame exactly this. |
| `world.railX` | `4.5` | Rails at ±corridorWidth/2. Camera is tuned so these sit at the frame edges at the squad plane, which is what makes the corridor read as bounded. |
| `world.clampX` | `4.2` | Squad centroid clamp, 0.3u inside the rail so a full-size formation never visually clips the railing. |
| `world.laneX` | `[-3.0, 0, 3.0]` | DERIVED as [-1,0,1] * corridorWidth/3. encounters.js authors lane INDICES, never absolute units, so a corridor-width change does not invalidate the level. |
| `world.scrollStart` | `14.0` | 8.2 soldier-heights/s: brisk but readable. With the 72u horizon this is a 5.14s engagement window, the budget the entire spawn table is written against. |
| `world.scrollEnd` | `18.0` | Ramps linearly to the boss gate, shrinking the window to 4.0s. This is the genre-canonical 'raise difficulty by cutting reaction time' — pressure rises with no new mechanics and no HP change. |
| `world.spawnHorizon` | `72` | THE budget. 72/14 = 5.14s of visibility at the start, 72/18 = 4.0s at the boss gate. Every barrel alpha below is a fraction of this window. |

| `camera.lookAt` | `[anchorX * 0.25 + velX * 0.06, 1.0, -7.5]` | Target y at chest height, z=-7.5 gives a 15.5° downward pitch — shallow enough to see far up the corridor, steep enough to read lateral position. The velX term is aim-ahead lead the player never consciously notices. |
| `camera.fov` | `62` | Portrait needs a tall vertical FOV to show corridor depth. Set with ACES tone mapping enabled on day one, because ACES desaturates and picking a palette before enabling it means picking it twice. |
| `camera.near / camera.far` | `1 / 200` | A 200:1 depth ratio instead of the default 20000:1 — two orders of magnitude more depth precision for free, killing most road z-fighting before a line of decal code is written. |
| `camera.followFactor` | `0.50` | PARTIAL follow. At 1.0 the squad is pinned to screen centre so dragging produces no on-screen motion of the thing you control and the input reads as dead at zero latency. At 0 the squad exits frame. |
| `camera.followTau` | `0.20` | Deliberately slower than the anchor spring (0.06) so the camera TRAILS the squad slightly — that lag is the parallax that sells the drag. |
| `camera.rollGain` | `0.012` | Counter-roll = clamp(-velX * 0.012, ±0.05) rad. Max 2.9°: felt, never consciously seen. Above ~4° it reads as a camera bug in portrait. |
| `camera.dollyZ` | `z = clamp(12.4 + 1.15 * log2(max(1,n)/3), 12.4, 15.6), y = 1.0 + 0.2773*(z+7.5)` | Log2 makes 3→6 soldiers a big framing change and 18→24 almost none, matching diminishing marginal value. The y formula holds PITCH CONSTANT so growth reads as 'the world got bigger', not as a camera angle change. |
| `camera.dollyOmega` | `3.0` | Deliberately slower than the lateral spring (omega 9) so a growth event is felt as a swell rather than a snap. |
| `camera.fovSpeedKick` | `(scrollSpeed - 14) / 6 * 3.5` | Up to +3.5° at max scroll: free perceived acceleration. Plus a -2.5° impact punch over 90ms restoring over 260ms on barrel death — asymmetric fast-in/slow-out is what makes it read as a hit rather than a zoom. |
| `camera.traumaDecay` | `1.6` | shake = trauma². A 0.30 barrel trauma is gone in ~190ms so consecutive breaks stack instead of the screen never settling. The square is what makes small events barely register and big events dominate. |
| `camera.trauma` | `{ soldierLoss: 0.35, barrelDead: 0.30, bossFootfall: 0.22, bossSlam: 0.45, bubbleShatter: 0.10, bossDeath: 1.00, ordinaryKill: 0.00 }` | Ordinary kills are EXPLICITLY zero. At 60+ kills a run, shaking on kills means the frame never rests and nothing reads as important. In portrait, over-shaking is actively nauseating. |
| `camera.shakeMaxAmp` | `{ yaw: 0.9°, pitch: 0.9°, roll: 1.4°, pos: 0.10 }` | Roll gets the largest allowance because rotational shake reads as FORCE while positional shake reads as a rendering error. |
| `fx.hitstop` | `{ barrel: [0.05, 0.070, 0.060], bossDeath: [0.02, 0.180, 0.120] }` | [timescale, holdSeconds, rampBackSeconds]. Reserved for these two gate events only — applying hitstop to ordinary kills makes the whole game feel like it is dropping frames. Suppressed entirely while a boss shockwave is in flight, or the dodge becomes unfair. |
| `fx.hitFlashDecay` | `8.0` | ~90ms, mixed at 0.85 not 1.0 so a hint of base colour survives and the actor stays identifiable while flashing. Under 60ms reads as a glitch; over 140ms reads as mushy. |
| `fx.damageAggregation` | `0.180` | Per-target window. Cuts number emission from ~100/s to ~5.5/s with 20 shooters, so each number represents a meaningful chunk instead of a 2.5-damage tick. |
| `fx.muzzleLife` | `0.055` | Short enough that 100 flashes/s blur into a continuous shimmer, which is correct. Lengthening it 'to be more visible' is exactly the wrong move. |
| `fx.ringRadius` | `{ soldier: 0.34, zombie: 0.36, brute: 0.52, boss: 3.2 }` | Ring radius IS the collision radius, made visible. Showing the hitbox is the single biggest anti-cheap move available in this genre. |
| `fx.fogDensity` | `0.0135` | FogExp2 at #D9BC8E gives 49% occlusion at the 72u spawn plane — completely hides pop-in while leaving silhouettes readable. The sky gradient's bottom stop must be this exact colour or a horizon seam appears. |
| `perf.pixelRatioMax` | `min(devicePixelRatio, 2.0) desktop / 1.5 mobile` | Fill rate, not entity count, is the real ceiling. DPR 3 on a 430x932 viewport is 3.6M fragments before a single additive layer. |
| `perf.dprDownshiftMs` | `20 over 30 frames` | Steps 2.0 → 1.5 → 1.25 → 1.0 and NEVER back up. Hysteresis, because an oscillating resolution is far more noticeable than a slightly soft one. |
| `pool.sizes` | `{ soldiers: 64, joiners: 24, zombies: 220, props: 12, boss: 1, shockwaves: 12, impacts: 256, tracers: 256, muzzle: 32, particles: 4096, glyphs: 96, decals: 64, rings: 320, eventRing: 2048 }` | All allocated at boot, never during play. resetWorld() sets every size to 0 — that IS the sub-100ms restart, and if it ever needs more, the pooling is wrong. |

## Entities

### Soldier
- **behavior:** The single resource: simultaneously HP, DPS and score, so every system reads through one integer. Occupies phyllotaxis slot i (a pure function of index, so gaining soldier N never moves 0..N-1); gameplay position resolves near-instantly around anchorX in sim/squad.js while the VISUAL position lags 90-200ms via per-soldier springs in view/characters.js — the two live in different layers so they can never be conflated. Fires independently on its own timer at the tier rate with a golden-ratio phase stagger, and EVERY timer produces real damage, so DPS is strictly linear in count. Only the front 14 emit tracers. Dies to zombie contact (1-for-1), barrel breach (proportional), or boss shockwave (2 per line).
- **collision:** Circle, 2D (x,z), radius 0.18. Zombie contact is PER SOLDIER (bigger squad = bigger target, but each hit costs the same 1 soldier and you have more to spare — it self-balances). Barrel gap tests use the squad CENTROID plus a FIXED 0.6u radius, never the crowd's real width, so growth is never a punishment. Mixing these two models up is the bug that makes getting stronger feel worse.
- **visual:** Merged non-indexed BufferGeometry from primitives with baked vertex colours, one InstancedMesh (capacity 64). The camera never sees a face, so the entire modelling budget goes to the REAR silhouette: helmet hemisphere r0.145 at y1.53 (topmost, brightest), backpack box 0.30x0.28x0.14 at z+0.16, rifle spar 0.06x0.06x0.62 past the right shoulder with the muzzle at local (0.20, 1.24, -0.52). Torso box 0.42x0.52x0.26. Height 1.70u, ~180 tris. Run cycle: legs ±0.62 rad at 2.6Hz with a knee fake (scale.y 1-0.12*max(0,sin(phase+1.1))), body bob, torso yaw — ARMS LOCKED FORWARD at -1.25 rad, never swinging, because a swinging-arm run under continuous auto-fire reads as broken instantly. Phase spread is a NARROW hash(id)*0.35 of a cycle: uniform random reads as a disorganised mob, narrow reads as a trained unit. Per-soldier scale 0.96-1.04, frozen ±0.06 slot jitter. Recoil spring omega 26 zeta 0.5 drives torso pitch +0.09 rad and gun z +0.05 — underdamped, so at 4+ shots/s it NEVER settles and the whole formation permanently shudders. That one float per soldier is the strongest 'we are shooting' signal in the game. Dual ground ring: dark #1A1611 contact ellipse (alpha 0.28, y 0.012) under an additive cyan #4FC3F7 glow ring (y 0.020, radius 0.34, 4Hz pulse). Death: dissolve over 220ms (scale.y→0.2 while scale.xz→1.4, alpha→0), NOT a ragdoll.

### Joiner (reinforcement in transit)
- **behavior:** Spawned at the broken bubble's position, one per rewarded soldier. Sprints toward the squad anchor at 16 u/s, invulnerable and non-colliding during the run-in, and merges into a formation slot with a ring flash and a +1 pop. Merges are staggered 60ms apart so the counter visibly TICKS UP. Run-in lasts 0.35-0.7s. Lives in sim/squad.js rather than its own module because a joiner is a squad member in transit and shares the slot allocator.
- **collision:** None. Deliberately non-colliding and invulnerable — a reward that can be killed on the way in is a reward the player is punished for earning.
- **visual:** Same instanced soldier rig at scale 0.2→1.15→1.0 on an overshoot spring (omega 18, zeta 0.45) over 340ms. A stretched additive beam from bubble to slot (90ms), then at the slot an expanding cyan ring 0.1→0.9 over 220ms plus 10 upward sparks. Global ring brightness jumps to 1.6x for 400ms. Seeing the reward physically travel and join is the payoff moment of the entire mode; silently incrementing a counter throws it away.

### Walker
- **behavior:** The baseline crowd. Spawns in loose clusters at the 72u horizon, advances at 5 u/s (closing ~19-23 u/s with scroll) and homes laterally toward anchorX at a RATE-LIMITED 2.5 u/s so it can be outrun sideways but not trivially. HP = 12 * 1.5^(t/50), scaling far slower than squad DPS on purpose: crowds get bigger, not tankier. BLOCKS BULLETS — a walker crowd standing in front of a barrel is a DPS shield that must be chewed through or sidestepped, which is the third axis of the allocation game. Dies to one contact, taking exactly one soldier with it.
- **collision:** Circle, 2D (x,z), radius 0.30. Contact test is per-soldier squared distance (0.18+0.30 = 0.48u) behind a scalar |z - squadZ| < 2.5 band reject that discards ~95% of zombies before any real test, because the squad occupies only a ~2u z band.
- **visual:** Merged instanced rig (capacity 220), height 1.85, shoulder width 0.72 vs the soldier's 0.52 — that width difference is the mass cue. Whole body pitched +0.38 rad (22°) TOWARD the camera with both arms locked at -1.5 ±0.25 rad reaching forward: the two forward-reaching arm bars are the most readable zombie cue at distance. Bare sphere head sunk between the shoulders and pushed forward, bobbing OUT of phase with the body so they read as uncoordinated rather than as recoloured soldiers. Asymmetric limp: legL amp 0.70, legR amp 0.42, with a -0.06u vertical hitch when the bad leg plants, cadence 2.0Hz. Rim light #E0503F at pow(1-dot(N,V), 3.2)*0.55 keeps them legible inside 49% fog. Red #E5484D ground ring at alpha 0.32. 0.35s spawn alpha fade. Hue can NEVER be the primary separator from soldiers (both must sit desaturated against sand) — silhouette and posture carry it, ring colour only confirms.

### Runner
- **behavior:** The reaction-time threat, introduced at t=40 once the player has learned to drag. HP 0.6x walker, speed 11 u/s (closing ~27 u/s), kills 1, blocks bullets. Also used for the crescendo's three scripted river sweeps at t=97/100/103, which occupy 6u of the 9u corridor and are a pure MOVEMENT test with no DPS answer — the channel that lets a weak-but-skilled player survive the crescendo.
- **collision:** Circle radius 0.26, same per-soldier rule. Sweep formations are tuned against the WIDE (2.1u radius) squad, so a strong player does not find the finale trivially dodgeable.
- **visual:** Same instanced rig at scale 0.92 with a leaner tint, cadence 3.2Hz and a deeper 0.48 rad forward pitch. Faster limp with a smaller amplitude asymmetry. Same red ring at radius 0.30.

### Brute
- **behavior:** Introduced at t=65. HP 8x walker (~156 at t=65 — half a second of full squad fire, a real diversion but never a wall), speed 3.5 u/s, kills 3 soldiers on contact, blocks bullets. Also absorbs the spawn-rate overflow when threat demand exceeds the 12/s body cap, so difficulty keeps climbing past the body limit.
- **collision:** Circle radius 0.55. Kills 3 in one contact, which is the only place a single body costs more than one soldier.
- **visual:** Same rig at scale 1.45 with a hypertrophied left shoulder, cadence 1.3Hz (cadence is a size cue independent of scale). The ONLY zombie carrying a visible HP bar, because it is the only one whose individual health is a decision worth making — health bars over 60 walkers would destroy readability entirely. Red ring at radius 0.52. Heavier footfall dust puffs.

### Barrel (role: wall | cheap | toll)
- **behavior:** Red drum cluster with its remaining HP printed camera-facing in large digits. Blocks bullets. Scrolls at world speed and must be shot down before it reaches the squad plane. Three roles differing only in alpha and lambda: WALL is full 9u width, mandatory, and blends HARD to your actual DPS (λd 0.85) so nobody is walled out of progress; CHEAP is 3.2u dodgeable and blends moderately; TOLL guards a bubble and stays pinned to par (λd 0.20) so the greedy lane is simply CLOSED to a weak squad and a flex for a strong one. On crossing: if the centroid+0.6u test does not overlap, clean dodge with a DODGED flourish and nothing else. If it overlaps, soldiersLost = clamp(ceil(n*F*(hpRem/hpMax)^1.5), 1, ceil(n*0.6)) — the 1.5 exponent makes a near-kill nearly free and ignoring one brutal. The barrel is then destroyed by the impact and THE SQUAD KEEPS MOVING AT FULL SCROLL SPEED; a lane runner that stops reads as a physics bug.
- **collision:** Axis-aligned x-extent test against the squad CENTROID plus a fixed 0.6u radius at the z-crossing frame. Blocks bullets over its full x-extent. Never the union of soldier bodies.
- **visual:** Plain Mesh (max 4 live, below the instancing threshold and each needs its own uniforms). Drum cluster with a fragment-injected VERTICAL FILL WIPE — fill = smoothstep(hpFrac-0.02, hpFrac+0.02, vUv.y) mixing healthy→damaged with a 0.06-wide hot emissive band at the boundary. This second non-numeric readout is what keeps the gate legible when the number is 30px tall at 60u. A canvas-baked crack texture mixes in as HP drops and the emissive pulse ramps 1Hz→6Hz, telegraphing 'about to blow' so the break feels earned. Wall variant adds yellow/black hazard stripes and a scrolling ground warning decal ahead of it; dodgeable variant has neither, so width class is readable at a glance. HP digits come from the shared glyph atlas as 1-4 instanced quads parented at local (0, 1.35, +0.62) facing +Z — no billboarding needed since barrels do not rotate — tinted green/amber/red by predicted TTK against current DPS, with a 1.22x scale pop over 110ms on each digit change so the number feels SHOT DOWN rather than merely decremented. Destruction: 70ms hitstop at 0.05x, trauma +0.30, FOV -2.5°, 12 fireball puffs (#FFE070→#FF5A1E→#3A2A26), a ground shockwave ring 0.5→6.0u over 380ms with a narrowing width (the single strongest scale cue), 10 debris dots, 6 drag-damped smoke puffs, a 120ms fullscreen additive flash at alpha 0.22, and 3 pre-authored chunk meshes tumbling for 1.2s — a barrel that simply vanishes always reads as cheap.

### Bubble
- **behavior:** The mode's signature twist and its central decision object. Translucent sphere floating at y=1.1, static in world space so it approaches at scroll speed. Carries HP at only alpha 0.16 (~0.8s of par DPS) — deliberately cheap, because the real cost is the SECONDS OF LANE OCCUPANCY stolen from the barrel next to it, and an expensive bubble turns a decision into a shooting chore. Blocks bullets. Always spawns as a PAIR in different lanes, one of which may carry a toll barrel in front of it. At 0 HP it shatters and spawns joiners (+k(t) soldiers) or increments the squad-wide weapon tier permanently for the run. If it reaches the squad unbroken it drifts past, desaturates, sighs, and shows a MISSED toast — WITH NO PENALTY, ever, because punishing a miss teaches players to avoid the most interesting decision in the game.
- **collision:** Circle radius 0.7 for bullet blocking. No body collision with the squad — it passes harmlessly through.
- **visual:** The ONLY additive-fresnel objects in the scene, which is what makes them impossible to miss. Icosahedron(0.85, 2) with alpha = 0.10 + 0.55*pow(1-dot(N,V), 2.4), tint #7FE8FF, AdditiveBlending, depthWrite:false, FrontSide, explicit renderOrder 10 over contents at 0 — three sorts transparents by object depth, which is meaningless for a shell that CONTAINS another object, and DoubleSide would make the two hemispheres self-sort wrongly. Never MeshPhysicalMaterial transmission: it forces a full extra scene render-target pass every frame and one bubble can eat 30-50% of the budget. Vertex wobble pos += normal*0.035*sin(pos.y*5+t*2.4). Contents are a real 3D object — three tiny soldier figures or a minigun silhouette — spinning at 0.6-0.8 rad/s with their OWN fake rim light, plus a 0.5Hz ±0.18 vertical bob, all so the reward type is identifiable from 72u where the player must commit. A thin emissive ring around the sphere DRAINS as HP falls, so partial progress is judgeable at distance ('can I finish this before it passes me'). Camera-facing canvas badge reads '+5' or 'MINIGUN'. Shatter: 18 shrinking shards at 4-8 u/s, an expanding additive ring 0.4→3.2 over 260ms on a pow(t,0.4) ease, a 90ms white flash sphere at scale 1.15, trauma 0.10.

### Boss
- **behavior:** The run's SCORE READOUT, not its difficulty peak — the crescendo at t=96-101 is where the build is actually judged, and if the boss were also brutal the player would get two failure signals and not know which to fix. On entry the world scroll decelerates 18→2→0 over 1.6s. HP = clamp(14*(0.55*parDPS(110) + 0.45*nominalDPS), 4600, 14400): the 0.45 blend keeps the fight from being trivial for a great run or a 45-second slog for a bad one. Three armour plates at 100/66/33%, each break granting a 1.2s stagger. Slams every 3.5s sending two expanding shockwave lines down the corridor with a 2.2u gap to slide between, each killing 2 soldiers on contact — this IS the entire damage model, so what kills you is always visible and dodgeable, with no abstract drain and no fail timer. Spawns two runner adds every 2.5s. A 30s rage timer shown as a draining ring halves both cadences on expiry: dangerous, never an instant loss. Fight ends on boss death (WIN) or soldiers reaching 0 (FAIL).
- **collision:** Circle radius 3.2 for bullet blocking; contact eats soldiers on touch. Shockwave lines are z-swept bands tested against the squad centroid plus formation radius — deliberately against the WIDE squad, so a strong player still has to thread them.
- **visual:** 7.2u tall (4.2 soldier-heights), same primitive vocabulary re-proportioned, with ONE hypertrophied shoulder (Sphere 1.05) and a normal opposite arm — asymmetry is what makes a low-poly kit read as a boss rather than a scaled zombie. Vertex-shader lump: pos += normal * (0.10*hashNoise3(pos*2.2) + 0.05*sin(pos.y*7.0 + t*1.5)). Violet #6B4A63, the only violet in the palette. Cadence 0.55Hz; EVERY footfall emits trauma +0.22, a ground dust ring and a 42Hz sine thud — the world reacting to its FEET, not just to its damage, is what makes it heavy. Hit flash is fresnel-weighted, mix(col, white, flash*(0.4+0.6*fresnel)), so it reads at scale without going fully white. MUST NOT FIT IN FRAME: the growth dolly is capped so its head crops or touches the top edge and it breaks the horizon line, and the entry punch-in looks UP at it (target y 2.6). Death: 180ms hitstop at 0.02x, then 1.2s at 0.35x while the camera orbits 12°, corridor floods with light.

### Shockwave (boss hazard)
- **behavior:** Spawned in pairs by a boss slam, expands down the corridor at 22 u/s with a 2.2u passable gap whose lateral position varies per slam. Kills 2 soldiers on contact. Advances during the sim's movement phase so it exists before collision runs and the dodge window is never 16ms late. Hitstop is explicitly SUPPRESSED while any shockwave is in flight, or the dodge becomes unfair.
- **collision:** A z-band swept against the squad centroid plus the current formation radius. Not per-soldier, because a partial clip costing a random number of soldiers would be unreadable at speed.
- **visual:** An additive ground ring quad expanding with a narrowing band width, plus a low vertical light wall so the gap is unmistakable from above the shoulder. Uses polygonOffset(-1,-1) rather than a y-lift, which looks correct near the camera and fails at exactly the far end of the corridor where the player is reading.


## Feel Checklist

- [ ] FOUR CHANNELS ON EVERY HIT, no exceptions: material hit flash (~90ms, mix 0.85), impact particles at the hit point, an aggregated damage number, and at the source a muzzle flash plus a recoil impulse. Fewer than four and the guns feel like they are firing into a void.
- [ ] The barrel's printed number starts ticking on the SAME FRAME the player slides into its lane. This closed loop IS the skill of the mode; verify it by dragging into a lane and watching the digit change with no perceptible gap.
- [ ] Permanent formation-wide recoil shudder. One float per soldier, spring omega 26 zeta 0.5, underdamped so at 4+ shots/s it never reaches rest. This does more for feel than any particle effect and must be in the first build.
- [ ] Two-tier position model VISIBLY working: gameplay position is instant (damage lands immediately) while the crowd sloshes behind it with radius-graded 90-200ms springs. If the squad feels like mud, the bug is that someone smoothed the input instead of the render.
- [ ] Dual-layer ground rings under every actor — dark contact ellipse UNDER additive glow. Removing this makes the mode unplayable: it is the primary lateral-position readout, the squad-count readout, the visible hitbox and the contact shadow all at once. Additive-only rings visually float.
- [ ] Partial camera follow at 0.50 with the lateral lean and counter-roll. Drag right and the squad must visibly MOVE right on screen. At 1:1 follow the input reads as dead even at zero latency.
- [ ] Rail posts whipping past at 6.4Hz with a rust stripe every 3rd post. The rails, not the road texture, are what carry forward speed.
- [ ] Soldier loss escalated to a SCREEN-LEVEL event: dissolve (not ragdoll), a red ring frozen at the death position for 0.4s, a large '-1' glyph, counter punch-scale + red flash, a red DOM vignette scaled by fraction-of-squad-lost, a low thud, and navigator.vibrate(20). Losing 1 of 40 is 2.5% of the crowd and is otherwise completely invisible — without this stack players never learn what killed them.
- [ ] Bubble break → soldiers physically SPRINT IN and merge one at a time, staggered 60ms. Three simultaneous merges read as one event; staggered they read as three gains. This is the single best half-second in the mode and a silent counter increment throws it away.
- [ ] Barrel destruction stack in one frame: 70ms hitstop at 0.05x, trauma +0.30, FOV -2.5°, fireball puffs, tumbling chunk meshes, and the ground shockwave ring 0.5→6.0u — the ring is the strongest scale cue and the chunks are what stop it reading as cheap.
- [ ] Digit pop: each HP digit scale-pops to 1.22 and back over 110ms when it changes, so the number feels shot down rather than decremented.
- [ ] Green/amber/red TTK tint on every barrel number. Without it the economy is invisible and the mode plays as a slot machine.
- [ ] Bubble contents legible at the 72u spawn plane: a real spinning 3D object with its own rim light, the drain ring, and the text badge. The player commits ~4s early; if they cannot read the lane the choice is a coin flip.
- [ ] Trauma-based shake with deterministic 3-sin value noise, granted ONLY on soldier loss / barrel death / boss footfall / boss slam / boss death. Explicitly zero on ordinary kills, and never per-frame Math.random, which reads as a rendering glitch rather than force.
- [ ] Per-shot audio randomisation of rate (0.92-1.08), filter (±12%), gain (±15%) and pan, with the compressor bus and the 9 voices/sec cap. An identical repeated sample at 5Hz is the number one audible tell of a cheap game.
- [ ] Narrow (0-0.35 cycle) run-phase spread, per-soldier scale 0.96-1.04, ±0.06 slot jitter. Uniform random reads as a disorganised mob; narrow reads as a trained unit with human sloppiness.
- [ ] touch-action:none plus preventDefault on the canvas, verified on a real phone. Without it iOS steals the drag as a page scroll or pull-to-refresh, which presents as 'the controls do not work'.
- [ ] Instant restart: tap or R to a fresh run in under 100ms with no scene teardown, no disposal, no reload. Frictionless retry IS the retention mechanic in this genre and it must work from the first playable build.

## Perf Budget

"TARGET: 60fps on a mid-range laptop at portrait letterbox. Sim ≤2ms, view sync + instance writes ≤2ms, submission ≤1ms, GPU ≤8ms, ~3.5ms headroom in 16.6ms. The debug overlay graphs these three separately so a regression is attributable to a layer on sight rather than by bisection.\n\nDRAW CALLS — target 28, hard ceiling 40. Itemised: sky 1, desert plane 1, road tiles 1 (instanced, modulo-z recycled), rail posts 1, rail beams 1, dark contact ellipses 1, additive glow rings 1, soldiers 1, zombies+brutes 1, tracer cores 1, tracer glow 1, muzzle flashes 1, particles 1 (ALL of them), decals 1, shockwave rings 1, glyph quads 1 (barrel digits AND floating damage numbers), lane guides + aim line 1, barrels ≤4, bubble shells ≤4, bubble contents 1 (instanced), boss 1, screen flash 1. HUD is DOM, so zero.\n\nTRIANGLES — ≤120k, expected ~60k. Soldier merged rig ~180 tris × 40 = 7.2k; zombies ~160 × 220 = 35k; boss ~1.2k; road, rails and props ~8k; particles are Points. Geometry is emphatically NOT the bottleneck.\n\nINSTANCING LINE, stated once so it is not relitigated per asset: 16+ concurrent objects sharing one geometry+material → InstancedMesh (soldiers 64, zombies 220, rail posts, tracers 256, muzzle 32, both ring layers, glyphs 96, decals 64, particles 4096). Below it → plain Mesh with per-object material control (barrels ≤4, bubbles ≤4, boss 1), because each genuinely needs its own uniforms — the HP fill wipe, the fresnel shell, the contents spin — and 9 extra draw calls against a 40-call budget costs nothing. BatchedMesh is refused outright: it targets many DIFFERENT geometries sharing one material, its instancing path emulates instancing via repeated multiDraw and benchmarks ~1.5-2x slower than true instancing, and this build is the textbook opposite case.\n\nTWO MANDATORY THREE.JS RULES. (1) frustumCulled = false on EVERY InstancedMesh whose matrices are written at runtime — three culls against the geometry's bounding sphere positioned at the mesh origin, so the whole horde silently vanishes when the camera looks slightly away, and the symptom does not obviously point at culling. (2) Every InstancedBufferAttribute needs its OWN needsUpdate flag separate from instanceMatrix.needsUpdate — setting only the matrix flag freezes gait phase and tint at boot values while positions animate correctly, producing a crowd that slides around without walking, with no error anywhere.\n\nCHARACTER PIPELINE. Build from primitives, bake per-part colour into a vertex-colour attribute and a per-vertex limbId, merge into ONE non-indexed BufferGeometry with mergeGeometries at boot, instance the result. Limbs animate via an onBeforeCompile vertex injection driven by a per-instance aPhase attribute, each patched material carrying a stable customProgramCacheKey. Verified against the installed three@0.185.1: there is NO InstancedSkinnedMesh, so SkinnedMesh would mean 200+ draw calls plus 200 skeleton updates, and a Group-of-primitives hierarchy would be 6 meshes per character. CLONE the merged geometry per InstancedMesh — sharing one geometry object between the soldier and zombie meshes breaks the moment their instanced attribute sets differ. Ship behind a LIMB_ANIM flag that zeroes the limb attribute for a static-mesh fallback, because the shader either compiles and animates or silently renders static with zero console output, and it must not be on the critical path to the first playable.\n\nMATRIX WRITES AND UPLOADS. Never Object3D.updateMatrix(); write the 16 floats directly with an inlined compose specialised for the actual case (near-uniform scale, Y yaw, small Z roll) — ~20 flops instead of the full quaternion path, at ~520 composes/frame peak. Views do a FULL REBUILD of every matrix from the pool's live range each frame and then set count = pool.size, never tracking instance indices: this costs ~0.1ms with the inline compose and makes the entire swap-remove reordering flicker class structurally impossible. Swap-remove keeps live entities as a contiguous prefix, so each mesh uploads exactly ONE range — and you must MUTATE attr.updateRanges[0] in place rather than calling addUpdateRange(), which I verified pushes a fresh {start,count} object literal on every call (node_modules/three/src/core/BufferAttribute.js:181) and would violate the zero-allocation rule in the exact loop that cares most.\n\nPOOLING. Every entity is a plain object pre-allocated at boot with a fixed monomorphic shape — deliberately NOT struct-of-arrays. At 40 soldiers + 220 zombies + 4096 particles the whole JS sim is 1-2ms of a 16.6ms budget, and a debugger showing {x:2.1, hp:40, kind:'walker'} beats an index into six parallel Float32Arrays. Sizes: soldiers 64, joiners 24, zombies 220, props 12, boss 1, shockwaves 12, impacts 256, tracers 256, muzzle 32, particles 4096, glyphs 96, decals 64, rings 320, event ring 2048. Two-phase death (markDead → single reap pass) plus generation-tagged handles make triple-kill-in-one-substep idempotent and stop a deferred impact damaging a recycled entity.\n\nZERO ALLOCATION IN THE FRAME LOOP, hard rule. Banned inside anything reachable from runStep() or a view update: object/array literals, new Vector3/Matrix4/Color, .filter/.map/.forEach with closures, and array splice for removal (swap-remove only). Scratch three objects live in view/scratch.js as the named enforcement point. Bus payloads come from a pre-allocated ring. Verified by a DEV heap-slope canary sampling every 2s plus a flat JS heap line across a full run — GC sawtooth in a 60fps runner is felt directly as input lag and is routinely misdiagnosed as a control problem.\n\nCOLLISION — there is no broadphase, and that is the answer the arithmetic gives. Choosing hitscan deletes the entire bullet-collision category: no travelling bodies, no swept segment tests, no z-grid, and no tunnelling (60 u/s at 60fps is 1.0 world unit of travel against a 0.4u radius; endpoint tests would silently miss ~60% of hits at range). Firing is ~4 rays/step worst case 64, each a walk over an x-sorted ~24-entry target array. Soldiers × zombies is 40 × 220 = 8,800 squared-distance tests (~0.09ms brute force), and a single scalar |z - squadZ| < 2.5 compare rejects ~95% before any real test because the squad occupies a ~2u z band. Everything is 2D (x,z) on squared distances; y is never read, which removes the class of bugs where an idle bob causes a phantom miss. The only data structure in the game is that one target array, rebuilt each step by an insertion pass that is O(n) because it is nearly sorted. Refused: octrees, BVH, three-mesh-bvh, Raycaster for gameplay, any physics library.\n\nFILL RATE IS THE ACTUAL CEILING. At ~350 instances the CPU is nowhere near its limit; the risks are additive tracer overdraw, the fresnel bubble shells, and fog at high DPR in portrait. Levers in order: setPixelRatio(min(dpr, 2.0 desktop / 1.5 mobile)); antialias only when DPR ≤1.5; adaptive downshift 2.0→1.5→1.25→1.0 after 30 consecutive frames over 20ms with NO upshift (hysteresis, because an oscillating resolution is more noticeable than a soft one); 1-in-3 tracer visual decimation above 40 shots/s with fire rate and damage unchanged; thicken the tracer stream rather than adding instances as the squad grows; hard cap of 4 concurrent bubble shells at low icosahedron subdivision. Additive fullscreen flashes capped at 0.25 alpha and 120ms under ACES at exposure 1.05, or additive VFX clip into flat magenta.\n\nTEXTURES. Zero runtime fillText anywhere. The 512² glyph atlas is baked once at boot; updating a barrel's number writes one float into an instanced UV-cell attribute over that barrel's slice only, and the matrix buffer is touched only when the DIGIT COUNT changes. Four barrels re-rasterising 512x256 RGBA per frame would be ~2MB/frame of upload and lands precisely when three numbers are ticking at once. Canvas colour maps get SRGBColorSpace; data maps (noise, alpha) stay NoColorSpace — the inverse error is equally destructive.\n\nZ-FIGHTING. near=1/far=200 gives a 200:1 depth ratio for free. Everything coplanar with the road — rings, blob shadows, decals, lane lines, shockwaves — uses polygonOffset(factor -1, units -1), NOT a y-lift of 0.02, which looks correct near the camera and fails at the far end of the corridor, i.e. it looks fine while you develop and breaks in the part of the screen the player is actually reading.\n\nREFUSED OUTRIGHT: EffectComposer/UnrealBloomPass (a full-res target plus ~5 blur passes at 3-6ms, manual output-colorspace handling, and it interacts badly with the transparent bubbles — faked instead with the dimmer second tracer instance and additive radial billboards, which takes ten minutes and looks better in this flat style); shadow maps (a 120u directional ortho frustum gives blurry peter-panning, roughly doubles draw calls, and the onBeforeCompile limb animation would not apply to the depth pass without separately patching customDepthMaterial, so animated characters would cast static T-pose shadows — blob shadows share the ring InstancedMesh); PointLights of any kind (muzzle spill is faked by lifting the gun's instanceColor and ring opacity for 55ms); MeshPhysicalMaterial transmission; logarithmicDepthBuffer; WebGPURenderer; GLTFLoader; AnimationMixer; CSS2DRenderer.\n\nRESTART falls out of the pooling rather than being engineered: resetWorld(seed) sets every pool size to 0, rewinds the beat cursor, clears the event ring and resets the scalars. Nothing disposed, nothing constructed, one frame, well under 5ms. Enforced by a DEV counter asserting zero geometry/material/texture constructions after boot. If a restart ever needs to touch the scene graph, the pooling is wrong — and that hitch would land at the exact emotional moment the genre cannot afford one."
